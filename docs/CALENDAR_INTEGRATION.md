# 📅 RFC 5545 iCalendar Export & Secure Subscribable Calendar Feeds

## 1. Overview & Architectural Principles

Phase 14 Cycle A introduces a comprehensive, standards-compliant calendar integration for the **Hierarchical Syllabus Checklist & Progress Tracker**.

Students can:
1. **Export static calendar files (`.ics`)** containing syllabus exam deadlines, academic milestones, and SM-2 spaced repetition review schedules.
2. **Subscribe to live, read-only calendar feeds** via token-authenticated URLs that external calendar applications (Google Calendar, Apple Calendar, Microsoft Outlook) periodically synchronize.
3. **Share `.ics` calendar files natively** on mobile devices (Android and iOS) via native share sheets or browser downloads.
4. **Prevent duplicate calendar events** through deterministic, stable event identifiers (`UID`).

---

## 2. Calendar Event Specification (RFC 5545 Compliance)

All calendar payloads generated by the application strictly adhere to RFC 5545:
- **Encoding & Line Breaks**: UTF-8 encoded with strict CRLF (`\r\n`) line endings.
- **Physical Line Folding**: Long property lines exceeding 75 octets are folded according to RFC 5545 Section 3.1. Continuation lines begin with a single whitespace character and never split multi-byte UTF-8 code points.
- **Text Escaping**: TEXT property values (`SUMMARY`, `DESCRIPTION`, `CATEGORIES`, `X-WR-CALNAME`) escape backslashes (`\\`), semicolons (`\;`), commas (`\,`), and newlines (`\n`).
- **All-Day Academic Event Timing**:
  - `DTSTART;VALUE=DATE:YYYYMMDD`
  - `DTEND;VALUE=DATE:YYYYMMDD` (exclusive end date: target date + 1 day).
  - Timezone-independent to prevent unintended calendar date shifting across geographic regions.

### 2.1 Exam & Target Deadlines
- **Event Identity**: `UID:deadline-{syllabus_id}-{node_id}@syllabustracker.app`
- **Summary**: `[Exam / Deadline] {node_title} ({syllabus_title})`
- **Categories**: `EXAM,DEADLINE,SYLLABUS`
- **Alarms**: Includes an RFC 5545 display reminder 1 day prior:
  ```text
  BEGIN:VALARM
  ACTION:DISPLAY
  TRIGGER:-P1D
  DESCRIPTION:Upcoming academic deadline
  END:VALARM
  ```
- **Description**: Detailed context containing the syllabus title, academic scope (subject or semester), full canonical breadcrumb path, completion percentage (`X/Y topics (Z%)`), and target completion date.

### 2.2 SM-2 Spaced Repetition Revisions
- **Event Identity**: `UID:revision-{syllabus_id}-{leaf_id}@syllabustracker.app`
- **Summary**: `[SM-2 Review #{repetitions + 1}] {leaf_title}`
- **Categories**: `REVISION,SPACED-REPETITION,SYLLABUS`
- **Description**: Contains the syllabus title, subject/module breadcrumb, leaf topic title, current review interval (`{interval_days}d`), easiness factor (`EF {ease_factor:.2f}`), repetition count, and next scheduled review date.

### 2.3 Stable UIDs & Update Behavior
Unlike basic calendar generators that create random UUIDs on every export (causing external calendars to duplicate events on each import), our implementation uses deterministic, immutable UIDs tied to canonical academic node IDs. When a student updates an exam deadline date or reviews an SM-2 topic (advancing its interval), calendar applications will update the existing event rather than spawning duplicates.

## 3. Strict Academic Invariants

### 3.1 Elective Exclusion Invariant
Any subject marked with `is_enrolled == False` (or status `excluded` / `pending`) and all its descendant modules and leaves are strictly excluded from:
- Downloaded `.ics` calendar files.
- Live calendar subscription feeds.
- Exam and milestone deadline events.
- SM-2 spaced repetition review events.

Descendants of unenrolled electives are filtered through the canonical hierarchy. If a student later enrolls in an elective, its deadlines and revision events automatically reappear in subsequent exports and feed requests without loss of historical progress.

### 3.2 Completion Filtering
- **Default (`include_completed = False`)**: Deadlines belonging to 100% completed academic branches are omitted from the schedule to keep the student's calendar focused on actionable, upcoming milestones.
- **Full History (`include_completed = True`)**: Completed academic branches are included and explicitly annotated with the `[Completed]` prefix in event summaries.
- **Past but Incomplete Deadlines**: Deadlines whose target date has passed but whose branch remains incomplete are preserved so students can see overdue requirements.

## 4. Secure Subscribable Calendar Feeds

External calendar providers (e.g. Google Calendar, Microsoft Outlook) cannot log in with student session cookies. However, exposing predictable syllabus IDs as public URLs is insecure.

### 4.1 Cryptographic Bearer Token Architecture
1. **High-Entropy Generation**: Tokens are generated using Python's `secrets.token_urlsafe(32)`, providing $\ge 256$ bits of cryptographic entropy.
2. **SHA-256 One-Way Hash Storage**: The plaintext token is never stored in the database. Only its SHA-256 hash (`calendar_feed_token_hash`) is persisted on the `syllabi` record.
3. **Constant-Time Verification**: Incoming feed requests hash the URL bearer token and verify it against the stored hash using `hmac.compare_digest`.
4. **Token Rotation**: Generating a new token immediately overwrites the stored hash, invalidating any previous calendar subscription URL.
5. **Revocation**: Students can revoke the calendar feed at any time via `DELETE /api/syllabus/{syllabus_id}/calendar/feed-token`, disabling access immediately.

## 5. User Guides

### 5.1 Exporting a Static Calendar File (`.ics`)
1. In the Syllabus Tracker header, click **Export & Backup**.
2. Select **Calendar Schedule (.ics)** (or **Share Calendar (.ics)** on Android/iOS).
3. The `.ics` file will download to your device or open the native operating system share sheet.

### 5.2 Importing a Static `.ics` File into Calendar Apps
- **Google Calendar (Web)**:
  1. Open [Google Calendar](https://calendar.google.com).
  2. Click the gear icon > **Settings** > **Import & export** (in left menu).
  3. Select the downloaded `.ics` file, choose the destination calendar, and click **Import**.
- **Apple Calendar (macOS / iOS)**:
  1. Double-click the `.ics` file or tap it in Files / Share Sheet.
  2. Choose **Add to Calendar** and select your desired calendar.
- **Microsoft Outlook**:
  1. In Outlook, navigate to **Calendar** > **Add calendar** > **Upload from file**.
  2. Select the `.ics` file and save.

> [!NOTE]
> Importing an `.ics` file creates a **static snapshot** of deadlines and reviews at the time of export. It does not update automatically when you review topics or adjust deadlines in Syllabus Tracker. For live updates, use a **Calendar Subscription Feed**.

---

### 5.3 Subscribing to a Live Calendar Feed
1. In the Syllabus Tracker header, click **Export & Backup** > **Subscribe to Calendar Feed...**.
2. If you haven't generated a link yet, click **Generate Subscription Feed**.
3. Click **Copy** to copy your unique, private subscription URL.
4. Add the URL to your calendar application:

#### Google Calendar
1. Open [Google Calendar](https://calendar.google.com).
2. In the left sidebar next to **Other calendars**, click the **+** (Add) icon.
3. Select **From URL**.
4. Paste your copied Syllabus Tracker subscription URL.
5. Click **Add calendar**.

#### Apple Calendar
1. Open the Calendar app on macOS or iOS.
2. In the menu bar, click **File** > **New Calendar Subscription...** (on iOS: **Calendars** > **Add Calendar** > **Add Subscription Calendar**).
3. Paste your subscription URL and click **Subscribe**.
4. Configure refresh interval (e.g., hourly or daily) and click **OK**.

#### Microsoft Outlook
1. Open Outlook on the web or desktop.
2. Open the Calendar view and click **Add calendar** > **Subscribe from web**.
3. Paste the subscription URL, enter a name (e.g. *Syllabus Tracker Schedule*), and click **Import**.

> [!IMPORTANT]
> **Refresh Timing**: External calendar providers (especially Google Calendar) manage their own background refresh schedules. Google Calendar typically polls subscribed feeds every 8 to 24 hours. Changes made in Syllabus Tracker will reflect on the next external provider sync cycle.

## 6. REST API Reference

| Method | Endpoint | Description | Auth Required | Cache-Control |
|---|---|---|---|---|
| `GET` | `/api/syllabus/{syllabus_id}/export/ics` | Export `.ics` file snapshot | Yes | Attachment |
| `POST` | `/api/syllabus/{syllabus_id}/calendar/feed-token` | Generate / rotate bearer token | Yes | No-Cache |
| `DELETE` | `/api/syllabus/{syllabus_id}/calendar/feed-token` | Revoke & disable public feed | Yes | No-Cache |
| `GET` | `/api/calendar/feed/{token}.ics` | Public live calendar subscription | Bearer Token in URL | `private, no-cache, max-age=300` |
